-----ภาพรวมโครงงาน (Project Overview)------

โครงงานออกแบบและพัฒนาฐานข้อมูลสำหรับระบบขายหน้าร้าน (Point of Sale: POS) และระบบสะสมคะแนนสมาชิกของร้านกาแฟ โดยใช้ Microsoft SQL Server เป็นระบบจัดการฐานข้อมูล

ระบบถูกออกแบบให้รองรับร้านกาแฟโดยทุกสาขาใช้ข้อมูลเมนู ราคา และสูตรวัตถุดิบจากส่วนกลางร่วมกัน แต่มีการจัดการสต็อกวัตถุดิบแยกตามแต่ละสาขา ลูกค้าสามารถสมัครสมาชิกด้วยเบอร์โทรศัพท์ สะสมคะแนน และแลกคะแนนเป็นส่วนลดได้ทุกสาขา

โครงงานมุ่งเน้นการออกแบบฐานข้อมูลเชิงสัมพันธ์ การควบคุมความถูกต้องของข้อมูล การจัดการธุรกรรม การกำหนดสิทธิ์ผู้ใช้งาน และการประยุกต์ใช้คำสั่ง SQL เพื่อรองรับกระบวนการทางธุรกิจ

🎯 วัตถุประสงค์ (Objectives)

เพื่อออกแบบฐานข้อมูลที่รองรับการดำเนินงานของร้านกาแฟหลายสาขา เพื่อเพิ่มความถูกต้องในการจัดการข้อมูลการขายและการชำระเงิน เพื่อจัดการและควบคุมสต็อกวัตถุดิบอย่างเป็นระบบ เพื่อรองรับการสะสมและแลกคะแนนสมาชิกระหว่างสาขา เพื่อกำหนดสิทธิ์การเข้าถึงข้อมูลตามบทบาทของผู้ใช้งาน เพื่อสนับสนุนการจัดทำรายงานสำหรับการบริหารจัดการธุรกิจ

🔍 ปัญหาที่พบ (Pain Points)

สต็อกวัตถุดิบคลาดเคลื่อนจากจำนวนที่มีอยู่จริง ข้อมูลการขายและการคำนวณยอดชำระเงินไม่ถูกต้อง การสะสมคะแนน การแลกคะแนน และการคืนคะแนนสมาชิกผิดพลาด ความเสี่ยงจากการเข้าถึงข้อมูลโดยไม่มีสิทธิ์ ความยุ่งยากในการบริหารจัดการข้อมูลระหว่างหลายสาขา

✨ ความสามารถหลักของระบบ (Key Features)

ระบบจัดการการขาย (Sales Management)
เปิดบิลและบันทึกรายการขาย รองรับขนาดสินค้า S, M และ L รองรับตัวเลือกเพิ่มเติม เช่น เพิ่มช็อตและลดความหวาน รองรับการชำระเงินสดและ QR Payment ใช้คะแนนสมาชิกแลกเป็นส่วนลด ยกเลิกบิลโดยได้รับการอนุมัติจากผู้จัดการ จัดเก็บราคาสินค้า ณ เวลาที่ขาย

ระบบจัดการสต็อก (Inventory Management)
จัดการสต็อกวัตถุดิบแยกตามสาขา ตัดสต็อกวัตถุดิบตามสูตรโดยอัตโนมัติเมื่อปิดบิล คืนสต็อกเมื่อมีการยกเลิกบิลที่ชำระเงินแล้ว บันทึกการรับวัตถุดิบและของเสีย ป้องกันการขายเมื่อวัตถุดิบไม่เพียงพอ ตรวจสอบวัตถุดิบที่ต่ำกว่าจุดสั่งซื้อ (Reorder Point)

ระบบสมาชิกและสะสมคะแนน (Membership & Loyalty System)
สมัครสมาชิกด้วยเบอร์โทรศัพท์ ตรวจสอบข้อมูลสมาชิกซ้ำ สะสมคะแนนทุก 25 บาท ต่อ 1 คะแนน ใช้ 100 คะแนน แลกส่วนลด 50 บาท ตรวจสอบวันหมดอายุของคะแนน รองรับการสะสมและแลกคะแนนข้ามสาขา ปรับปรุงคะแนนสมาชิกเมื่อมีการยกเลิกบิล

ระบบจัดการข้อมูลส่วนกลาง (Centralized Management)
จัดการหมวดหมู่และข้อมูลสินค้า กำหนดขนาดและราคาสินค้า จัดการสูตรและปริมาณวัตถุดิบ จัดการตัวเลือกเพิ่มเติมของสินค้า กำหนดสถานะการจำหน่ายสินค้า

ระบบรายงาน (Reporting System)
รายงานยอดขายรายวันแยกตามสาขา รายงานยอดขายรายเดือนแยกตามสาขา รายงานสินค้า 10 อันดับขายดี รายงานวัตถุดิบใกล้หมด รายงานสมาชิกที่ไม่มีการซื้อสินค้าเกิน 90 วัน

ระบบรักษาความปลอดภัย (Security & Audit Log)
กำหนดสิทธิ์การเข้าถึงข้อมูลตามบทบาทผู้ใช้งาน จำกัดการเข้าถึงข้อมูลตามสาขา ปกปิดเบอร์โทรศัพท์ของสมาชิก (Data Masking) ตรวจสอบตัวตนและสิทธิ์ของพนักงาน บันทึกประวัติการเปลี่ยนแปลงราคาสินค้า บันทึกประวัติการยกเลิกบิล

👥 ผู้ใช้งานระบบ (User Roles)

HQ = จัดการข้อมูลสินค้า ราคา สูตรวัตถุดิบ และตรวจสอบรายงานทุกสาขา Manager = จัดการสต็อก รับวัตถุดิบ บันทึกของเสีย และอนุมัติการยกเลิกบิล Cashier = เปิดบิล เพิ่มรายการสินค้า สมัครสมาชิก และรับชำระเงิน Member = ตรวจสอบข้อมูลสมาชิก คะแนนสะสม และประวัติการซื้อของตนเอง

🛠️ เทคโนโลยีและเครื่องมือ (Technologies & Tools)

Microsoft SQL Server SQL Server Management Studio (SSMS)

🗄️ การออกแบบฐานข้อมูล (Database Design)

ฐานข้อมูลถูกแบ่งออกตามกลุ่มการทำงานของระบบ เพื่อให้ง่ายต่อการบริหารจัดการและลดความซ้ำซ้อนของข้อมูล กลุ่มการทำงาน ตารางฐานข้อมูล ข้อมูลองค์กร Branch, Employee ข้อมูลสินค้า Category, Product, ProductSize, ProductOption ข้อมูลสูตรและวัตถุดิบ Ingredient, Recipe ข้อมูลการขาย Sale, SaleItem, SaleItemOption, Payment ข้อมูลสต็อก Stock, StockTransaction ข้อมูลสมาชิก Member, PointsTransaction ข้อมูลประวัติการทำงาน AuditLog

📋 กฎทางธุรกิจ (Business Rules)

1.ทุกสาขาใช้เมนูและราคาสินค้าจากส่วนกลางร่วมกัน 2.แต่ละสาขามีสต็อกวัตถุดิบเป็นของตนเอง 3.ทุกยอดซื้อสุทธิ 25 บาท ได้รับ 1 คะแนน โดยปัดเศษทิ้ง 4.ทุก 100 คะแนน สามารถแลกส่วนลดได้ 50 บาท 5.คะแนนสมาชิกหมดอายุในวันสิ้นปี 6.สต็อกวัตถุดิบต้องไม่ติดลบ 7.ไม่สามารถขายสินค้าได้หากวัตถุดิบไม่เพียงพอ 8.ต้องจัดเก็บราคาสินค้า ณ เวลาที่ขาย 9.สินค้าที่เคยขายแล้วต้องใช้การเปลี่ยนสถานะแทนการลบข้อมูล (Soft Delete) 10.การยกเลิกบิลต้องได้รับการอนุมัติจากผู้จัดการ 11.การเปลี่ยนราคาและการยกเลิกบิลต้องมีการบันทึก Audit Log
